Prácticas clave de DevOps

Integración Continua (CI)

Combinar los cambios de todos los desarrolladores varias veces al día en un repositorio compartido.

Cada integración se verifica con una build automatizada y pruebas automáticas para detectar errores lo antes posible. Reduce los conflictos de integración y mantiene el código siempre en un estado desplegable.

  • Azure Pipelines
  • GitHub Actions
  • Jenkins

Entrega Continua (CD)

Automatizar el despliegue de cada cambio validado en un entorno de preparación o producción.

Los artefactos generados en la fase de build se publican mediante pipelines con aprobaciones manuales y estrategias como despliegue azul/verde o canary para minimizar el riesgo.

  • Azure Pipelines
  • GitHub Actions
  • ArgoCD

Infraestructura como Código (IaC)

Gestionar la infraestructura mediante archivos de definición versionados en el repositorio.

Permite crear, modificar y destruir entornos de forma reproducible y auditable. Los cambios en la infraestructura se revisan mediante pull requests igual que el código de la aplicación.

  • Terraform
  • Bicep
  • ARM Templates
  • Pulumi

Monitorización y Observabilidad

Recopilar métricas, logs y trazas para conocer el estado real de la aplicación en producción.

Los dashboards y alertas permiten detectar incidentes antes de que los usuarios los noten, y alimentan el ciclo de mejora continua con datos reales del funcionamiento del sistema.

  • Azure Monitor
  • Application Insights
  • Prometheus
  • Grafana

DevSecOps

Integrar la seguridad en todas las fases del ciclo de desarrollo, no solo al final.

Incluye análisis estático de código (SAST), escaneo de dependencias, análisis de contenedores y pruebas de seguridad automatizadas dentro del pipeline de CI/CD.

  • Dependabot
  • SonarQube
  • Trivy
  • Microsoft Defender for Cloud

Conceptos de computo en la nube

Modelos de servicio en la nube

IaaS, PaaS y SaaS: distintos niveles de responsabilidad entre el usuario y el proveedor.

En IaaS se gestionan el sistema operativo y las aplicaciones; en PaaS solo el código y los datos; en SaaS solo el uso del producto. Azure DevOps es un servicio SaaS para el ciclo de desarrollo.

  • IaaS
  • PaaS
  • SaaS

Escalabilidad y elasticidad

Capacidad de crecer o reducir recursos según la demanda de forma automática.

La escalabilidad vertical aumenta la potencia de una máquina; la horizontal añade más instancias. La elasticidad ajusta la infraestructura automáticamente para optimizar costos.

  • Autoescalado
  • Balanceo de cargas
  • Costo optimizado

Contenedores y orquestación

Empaquetar la aplicación con sus dependencias para ejecutarla de forma consistente en cualquier entorno.

Docker estandariza la imagen del contenedor y Kubernetes orquesta su despliegue, escalado y recuperación ante fallos. Ambos son piezas clave de las arquitecturas modernas en la nube.

  • Docker
  • Kubernetes
  • Azure Kubernetes Service

DevOps en la nube

Servicios gestionados que cubren todo el ciclo de desarrollo: planificar, construir, probar y desplegar.

Azure DevOps integra Repositorios, Boards, Pipelines y Artifacts en un solo servicio. Las pipelines pueden desplegar a Azure App Service, AKS, Azure Functions o VMs con tan solo definir un archivo YAML.

  • Azure DevOps
  • Azure Pipelines
  • Azure Repos

Fiabilidad y recuperación ante desastres

Diseñar sistemas que toleran fallos y permiten restaurar el servicio rápidamente.

Incluye redundancia multi-región, copias de seguridad automáticas, los acuerdos de nivel de servicio (SLA) y los objetivos de tiempo de recuperación (RTO/RPO).

  • SLA
  • RTO/RPO
  • Alta disponibilidad

Etapas de un pipeline de despliegue

  1. 1. Repositorio El código se versiona en Azure Repos o GitHub y los cambios entran mediante ramas y pull requests.
  2. 2. Build El pipeline compila la aplicación, ejecuta las pruebas y genera un artefacto versionado.
  3. 3. Análisis Se ejecutan escaneos de seguridad y calidad de código (lint, SAST, dependencias).
  4. 4. Despliegue a QA El artefacto se publica en un entorno de pruebas automatizadas para validación.
  5. 5. Aprobación Una validación manual o automática habilita el paso a producción.
  6. 6. Producción Despliegue progresivo con monitorización y posibilidad de reversión rápida.
